## Тексты issues

### 1. Список виновников по категориям
Сделать `data.py` с категориями от бытовых до абстрактных. Критерий: минимум 10 виновников в категории.

### 2. Детерминированный выбор виновного по хешу
Выбор по SHA-256 нормализованного текста. Критерий: один ввод даёт один ответ независимо от регистра и пунктуации.

### 3. Фильтр «ответ не связан с вводом»
Исключать виновных и обоснования с общими основами слов. Критерий: тест на каждом виновном из базы.

### 4. Процент уверенности и обоснование
Уверенность 51-99%, шаблоны обоснований. Критерий: обоснование упоминает виновного.

### 5. Уровни абсурда 1-5
Уровень N использует первые N категорий. Критерий: ошибка при уровне вне диапазона.

### 6. CLI и вывод в JSON
`python -m vinovatornik [--level N] [--json] текст`. Критерий: код возврата 2 при ошибке.

### 7. CI на self-hosted runner
Workflow `.github/workflows/ci.yml`, раннер на своей машине. Критерий: зелёный прогон с тестами во вкладке Actions.

### 8. Страницы вики
Минимум 5 страниц: Home, Architecture, Algorithm, Process, Testing-and-Deploy, плюс Roadmap и Team.

### 9. HTTP API
Эндпоинт `POST /blame` с JSON `{"text": "...", "level": 3}`. Зависит от стабильного формата `Verdict`. Реально реализуй в отдельной ветке `feature/9-http-api` и оформи PR.

### 10. Dockerfile и релиз v1.0.0
Образ с запуском CLI, тег `v1.0.0`, GitHub Release. Зависит от Docker-среды команды «Платформа» (см. [Роадмап](https://github.com/<ты>/vinovatornik/wiki/Roadmap)).

## Как показать процесс

1. Первым PR залей весь готовый код с описанием `Closes #1, closes #2, closes #3, closes #4, closes #5, closes #6`.
2. #7 закрой PR с `ci.yml`, когда раннер заработает.
3. #8 оставь в Review, пока не зальёшь вики.
4. #9 реально сделай в ветке, и пока PR открыт, держи задачу в In Progress.
5. #10 оставь в Backlog.
6. Заполни Assignee (на себя), даты старта и окончания для вида Roadmap.
